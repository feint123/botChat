botChat 1.1.13

本次两支主线：空态从「静态欢迎页」变成有内容的一面墙（活跃热力图 + 每日生成的建议），以及出站边界新增一层可选的凭据脱敏；此外是对 1.1.12 跨会话记忆的审查收尾，与热力图落地后暴露的两处真故障修复。

新增

  • 空态活跃热力图：按自然日展示你的发言条数，连续与空档一眼可辨；数据由服务端按日物化（缺省每 15 分钟重算「过去 7 天 + 今天」，时区缺省 Asia/Shanghai），接口只读汇总表、请求内不做聚合。
  • 热力图零请求渲染：客户端渲染路径直接读本机日缓存，不发任何请求；可见期间不替换已画出的快照，图和文案不会自己跳一下。
  • 出站凭据脱敏（默认关）：请求发出前把会话内容里的私钥块、供应商 key、JWT、URL 凭据、.env 赋值、邮箱、卡号、身份证换成可逆占位符 BOTCHAT_SECRET_*，回程再还原成真实值；规则全在本地、零出网。
  • 设置 → 隐私：脱敏开关加「试算预览」——粘贴一段文本（.env 行、连接串、日志片段均可）即可看到真实链路上模型会看到什么，只回掩码后的文本与命中类型计数，不回任何原值。

改进

  • 空态建议胶囊改为按日生成：不再由「项目名 / 分支 / 未提交」三句固定话术派生，改为小模型按工作目录每天生成一次（输入是项目、前一天的会话摘要、近 24h 提交与当天日期节日）；合格条目不足 3 条就整批作废，回落到内置的热门提示词池。
  • 胶囊改两段契约：显示的是短标题（不超过 16 字），点击填入的是完整稿；仍只填入、不自动发送。
  • 胶囊布局响应式：宽档横排居中、窄档竖排左对齐，切换阈值带 48pt 滞回，拖动窗口时不会来回抖。
  • 新增「Composer 建议」开关：可关掉小模型生成、只用固定热门提示词，界面上写明会发出哪些信号。
  • 努力度电弧齿距修正：high 档原先齿距密到相邻齿被光晕填满、读作一条噪点带，现按归一化宽度锚定全宽周期数，齿数恒定，采样密度由 5pt 提到 2pt。

修复

  • 热力图在默认列宽下只能看到约 56%：内容宽原写死 608.5pt，而对话列默认可用宽只有 339pt，横向滚动条又被隐藏，于是全年被裁、图例只剩「未活跃」三字，最大化窗口也不会变宽（列宽是持久化值）。现在几何按可用宽求解，只有把列拖到 320pt 下限才需要滚动，而那种情况下滚动条可见、不再把「被裁」伪装成设计。
  • 热力图与输入条左右不对齐：此前热力图铺满整个对话列、首末列被列边界切掉；留白改由组件自己按与 composer 同源的 12pt 处理，两侧像素级对齐。
  • 热力图顶栏随格阵被滚走：统计三元组与图例移出滚动内容，宽度取可见块宽而非内容宽；月份标签仍与格阵同处一段滚动内容，避免滚动时与列错位。
  • 内嵌服务端跑 SQLite 时热力图一行数据也没有：日界折算只按 Postgres 的 AT TIME ZONE 写，SQLite 上每轮都失败；现按方言分支，并补上 SQLite date() 返回字符串的解析。已知偏差：区间跨 DST 切换时边界日差一小时（内嵌默认时区无 DST）。
  • 内嵌服务端换端口后空态取数落空：客户端 store 持有了启动时拍下的地址快照，而后端真实端口是随后写入的；取数改为每次新建服务（工厂注入），sidecar 换端口后自愈。
  • 满容量的合法记忆必然显示「已截断」：截断预算改按条目字符判定，块头、分节标题与 § 分隔行这些固定开销不再算进任何一级的容量。
  • 记忆写入的三处语义漏洞：patch 现在要求给出改写后的完整条目（此前给片段会连带抹掉同一条里的其它事实）、未知 action 显式失败（此前会落进 patch 分支并「成功」整条覆盖）、内容含 § 分隔符直接拒绝（一条会落成多条，且此后无法再定位）。
  • 容量报错误导判断：错误体里的 usage 改报当前占用（此前装的是写入后的预测值，看到 2352/2200 会误判成「库已经爆了」），并带千分位与实时配置的上限。
  • 收尾归档的两处丢数据：归档输出预算独立为 1024（沿用标题链的 256 会把 JSON 数组截断成非法 JSON 而整批丢弃）；同一会话归档未结束时又收到收尾，不再直接丢弃候选，改为排队补跑一次。
  • 记忆护栏的漏检：中文注入词各段之间带空白的最平凡变体此前漏检；补上 Google API key、JWT、Authorization: Bearer、带口令的连接串、改写 authorized_keys 的 SSH 后门五类凭据；不可见字符区间扩到 TAG 字符与变体选择符。
  • 记忆注入的第四条生效路径：快照读不懂时（extra_metadata 为 NULL 或结构非法）此前被折成 None，下一跳就落进「新会话」分支，每次读盘覆盖已冻结的快照、打穿整个会话的前缀缓存；现在读不懂就零注入。
  • 记忆文件可能被符号链接劫持：os.replace 会把链接本身换成普通文件，此后每次「成功」写入都落在没人编辑的新文件上，用户手改真文件也不再被注入；现在直接拒绝符号链接。
  • 删陈旧锁会误删别人的锁：锁改按 inode 复核，释放前只删自己建的那把，不再让第三个写者立刻入场。

其他

  • memory 内置 MCP server 与 skills/memory-via-bash（用 bash 手改记忆文件的旧办法）一并下线，记忆只走 memory 工具与直接编辑两个 Markdown 文件两条路。
  • MEMORY_* 配置语义归位：MEMORY_ENABLED 明确为含收尾归档的总闸，MEMORY_TOKEN_LIMIT 回归「模型窗口未知时的兜底」；.env.example 换成真实的键名。
  • 新增三份迁移（activity_day 表、empty_state_suggestion 表、outbound_masking 设置行），随服务端启动自动执行，无需手工操作；自建部署且设了 SKIP_MIGRATIONS=1 的环境需自行执行 alembic upgrade head。
