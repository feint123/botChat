botChat 1.1.10

本次更新主线是「思考与档位从猜变成可判定」：思考流按契约表拆成三层、实际下发档位收敛到唯一出口，并修掉 WorkBuddy 上游恒 0 思考 token；同时修掉输入条 @ 引用 chip 只剩折角占位图、主轮 compact 恒缺上下文、以及委派失败的真实成因（记账与业务事实共用一条长事务）。

新增

  • 思考契约表：上游不再靠逐个 getattr 猜「思考用哪个键名」——每家 provider 用纯数据声明回传键名、缺思考是否补空串、是否必须带档位，读取收敛到唯一出口。12 家 OpenAI 兼容 provider 的历史报文逐字节不变，新增上游不必再在解析层追加兜底链。
  • 实际下发档位的唯一出口：目录为空不传、越界就近夹取（平手取高）、上游必须带档位则补模型默认档、异常落 warning 并如实不传；Supervisor 主轮与 worker 两条流共用同一出口，worker 不继承用户档位却仍能满足「必须带档位」的上游。
  • 档位链路两处观测点：新增「最终解析出什么档位」（带分支原因、目录来源、动态目录是否命中）与「档位是否真写进了请求体」两条日志，此前「上游就是不思考」「本层回落成不传」「传了但上游不认」三种处境无法区分。

改进

  • 思考搬运与补位拆成两个正交判定：历史里已有的思考「搬不搬」与「缺思考要不要补空串」此前被耦合成一处，现在各自独立，报文输出对既有 provider 零变化。
  • 面板头部移除分隔竖线：头部与操作簇之间、按钮之间的发丝竖线一律移除，分界改由留白表达，按钮分组交给图标语义。
  • 内嵌服务端改为每次构建都同步：此前只在 Release 嵌入，Debug 进程优先读 bundle 里的旧副本，改 Python 后「修复无效」；现依赖变则重打包、源码变则只同步代码、已最新则零动作，签名责任也划清（只签内层，外层交给 Xcode 或打包脚本）。

修复

  • WorkBuddy 恒 0 思考 token、界面永远没有思考块：agent loop 每轮重建请求时漏采档位字段，档位在进入循环后被静默重置为「不传」，对「不传即不思考」的上游直接失效。已补采并加回归锁，新增上游旋钮字段漏采会立刻变红。
  • 输入条 @ 引用 chip 只剩折角纸片 / 首行按占位尺寸排版：实测给 attachment 设了尺寸或图片任一项，框架即走静态占位分支、chip 视图根本不挂载；现两者保持为空，布局尺寸只由 provider 报出，行内重排收敛到唯一出口，并补「真实窗口 + runloop」的回归锁。
  • @ 引用 chip 的浮层几何与裁剪：自写的高度上限比外层硬上限多 8pt，候选行被静默裁掉一截；几何参数收敛到唯一出处。
  • 主轮 compact 恒返回缺少上下文：compact 的会话/run 此前只由私有 ContextVar 喂，Supervisor 主轮没有写入点；现改由上下文注入，作用域退出走 token 复位，嵌套场景不再把外层的值抹空，失败返回体也补了成因与提示。
  • 并发委派偶发整体失败：用量记账与业务事实共用同一条贯穿整个模型流的长事务，记账撞锁会把同事务里尚未提交的状态事实一起回滚，表现为「记账失败 = 委派失败」。记账改为自持短事务，持锁窗口从整条流缩到两条语句；数据库异常归一为死锁 / 锁超时 / 序列化冲突 / 连接池超时 / 完整性约束五类，连接池超时明确不重试。
